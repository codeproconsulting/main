# Session 2026-10-29-03: CMS-03

## Focus and boundary

Visual authoring, revision restore, and scheduled publication. Previous CMS-02 evidence is preserved in `2026-10-29-02-state.json`. No production worker, public provider switch, or real content publication was authorized as part of these checks, and none was performed.

## Fixes

- Editors cannot publish, schedule, or modify a scheduled/live article through an apparent draft transition.
- Publishing and scheduling reject empty sanitized content. Schedules require a future timestamp with a timezone. Publish-now replaces a future scheduled date; ordinary edits preserve an existing publication date.
- Snapshots are deterministic per article/version, retry-safe after a failed write, and verified before reuse. Restores reject another article's revision and stale versions, preserve URL/current publication state/legacy metadata, and retain another snapshot.
- Durable audit intent precedes article mutation; unavailable audit storage prevents an unaudited mutation. A later acknowledgment/audit-completion failure can leave a pending intent for operational review.
- Visual content initialization uses stable memoized markup. Browser testing exposed and reproduced an input-clearing bug before this fix. Selection is retained for toolbar commands, pasted/dropped text is inserted as text, and source HTML is sanitized on the server before returning to visual mode.
- The editor/form resets from the canonical saved version. Browser testing exposed stale future date values after publish-now; the corrected form displays the actual saved timestamp.
- A dedicated publishing runner is independent of the unaccepted reminder runner and disabled by default.

The posts schedule index was added using collection-scoped additive setup. A read-only live query confirmed it available and found zero due scheduled posts. This did not invoke a worker or publish anything. Real imported posts were not used as test subjects.

## Recovery limits

Locks fail closed after a process crash; safe operator recovery requires stopping potential writers and inspecting the exact abandoned lock. Lost acknowledgments can leave pending audit intents that require comparison with the persisted post/version. This is explicitly documented rather than described as fully transactional exactly-once delivery. See `docs/SCHEDULED-PUBLISHING.md`.
