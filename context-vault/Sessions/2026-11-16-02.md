# CRM-03 branch and team access design

## Current authorization map

| Surface | Current enforcement | Required before restricted managers can use it |
| --- | --- | --- |
| Lead list, counts, direct detail and native mobile API | `crm.server.ts` uses organization-wide manager access and assignment-only counselor access. Mobile reuses these functions. | Apply an indexed team filter before list counts or pagination and enforce the same team on every direct read and mutation. Load current staff scope on web and mobile requests. |
| Matching enquiries, contact groups and duplicates | Matching and confirmed group lists query lead records. Duplicate resolution checks both records under locks. | Filter lists and totals before pagination. Require both records in scope for links and decisions. Suppress a retained reference if its target is outside the reader’s scope. |
| Tasks, applications and appointments | `scopedQueue` filters counselors by owner and checks current lead access. Manager task reads can skip the lead check. Direct operations resolve the parent lead. | Scope lists by a reviewed team projection before returning totals or rows and recheck the current lead. Remove the global manager shortcut from restricted paths. Calendar conflict detection may check outside the visible team but must reveal only that a slot is unavailable. |
| Notes, audit, private documents and notification inbox | Lead detail resolves access before querying activities. Document upload, review and download resolve the parent. Inbox checks recipient and current lead. | Keep the lead check at every entry point, including download and mutations. Restrict worker health and independent operational metadata to global administrators. Verify recipient and parent checks after reassignment. |
| Consultation list and reporting | Consultation logs resolve lead access. Manager consultation listing and operational report/CSV queries are organization-wide. | Apply team scope before aggregation, directory lookup or CSV generation. Disable report/CSV and consultation overview for restricted managers until these paths have scoped queries. |
| Assignment, roster and staff profiles | Bulk assignment, routing settings and round robin use role checks. Staff administration is owner/admin-only. The intake worker uses a configured manager actor. | Validate target and current parent team under the existing staff-access lock. Scope manager roster and routing settings by team. Keep organization-wide intake routing under a global actor until an explicit intake team mapping exists. |

## Proposed access defaults

- Owners and administrators retain organization-wide CRM access. Counselors retain assignment-only access.
- Introduce an explicit manager scope. Preserve current access for existing managers until an administrator confirms a migration. Require an explicit scope for newly configured managers once the feature is enabled. Restricted managers without a valid active team receive no team records.
- Use a private team directory with one branch per team. First release managers manage one team. Branches group teams for administration and do not grant additional access.
- Store the managing team on the enquiry, independent of the assigned counselor. A reassignment within that team keeps the team. Cross-team moves and unresolved or unclassified intake remain with global administrators. Never infer a branch from destination, applicant location or service label.
- Treat the current parent enquiry as authoritative for linked access. A derived team value may support a list query, but a mismatch must hide the linked record until reconciled. Keep the existing lead and staff locks through any multi-record handoff.

## Migration and release order

1. Add private directory and optional staff and enquiry scope fields with the feature disabled. Inventory missing teams, invalid references, mixed linked records and unassigned enquiries using aggregate counts only.
2. Administrators confirm membership and classify enquiries. Backfill in bounded, resumable batches. Preview first, preserve previous assignments, and leave ambiguous enquiries in the global intake queue.
3. Implement common policy and indexed lead queries. Add two-team acceptance for read by ID, lead search/count, mobile reads, bulk assignment and stale session/role changes. Until linked surfaces are verified, deny those surfaces to restricted managers server-side.
4. Verify linked queues, docs, consultations, reports, exports, reminders and cross-team handoff failures before opening each surface. Test that counts, names, audit payloads and CSV rows cannot cross teams.
5. Enable selectively after target Appwrite and runtime checks pass. If rollout must be reverted, disable restricted-manager CRM access or revert to a build that denies these accounts. Never restore global access implicitly. Keep schema and audited assignments available for reconciliation.
